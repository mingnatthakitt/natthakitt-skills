# Manuscript — Research Documentation Generator

Produces a comprehensive, academically-styled research manuscript about the codebase, integrating deep code analysis with LaTeX-formatted equations, formal citations, and publication-ready structure.

**IMPORTANT:** When this skill is invoked, you MUST:
1. Conduct deep codebase exploration
2. Cross-reference with existing wiki if available
3. Create ACTUAL files using Write tool — do not just describe what to generate

## Trigger Conditions

- User invokes `/manuscript`
- User asks to "create a research paper", "write a technical report", "generate a manuscript"
- User requests an "academic analysis", "formal documentation", or "detailed study" of the codebase
- User wants to "document with equations", "add citations", or "produce a paper"

## Generation Process

### Phase 1: Deep Codebase Exploration

Use Bash and Read tools to thoroughly analyze:

1. **Structural Analysis**
   - `ls` the project structure recursively
   - Read all source files (`.ts`, `.js`, `.py`, `.go`, `.rs`, `.java`, etc.)
   - Map directory structure and module organization
   - Identify entry points and main components

2. **Semantic Analysis**
   - Understand core algorithms and data transformations
   - Trace data flow through the system
   - Identify state management patterns
   - Map API contracts and interfaces

3. **Pattern Recognition**
   - Design patterns in use (GoF, architectural patterns)
   - Concurrency patterns (if applicable)
   - Data persistence patterns
   - Communication patterns (sync, async, event-driven)

4. **Workflow Mapping**
   - Build processes
   - Test execution flows
   - Deployment pipelines
   - CI/CD workflows

### Phase 2: Wiki Cross-Reference

If `.claude/wiki/` exists:
1. Read existing documentation files
2. Cross-validate understanding
3. Use as foundation to build upon

### Phase 3: Create All Manuscript Files

Use Write tool to create each file. Create ALL of the following:

#### 1. manuscript.tex
Complete LaTeX document with:

```latex
\documentclass[12pt]{article}
\usepackage{amsmath, amssymb, graphicx, hyperref}
\usepackage[utf8]{inputenc}
\usepackage{cite}

\title{Systematic Analysis of {Project Name}}
\author{Generated by Claude Code}
\date{\today}

\begin{document}

\maketitle

\input{abstract}

\section{Introduction}
% Generated content with LaTeX equations

\section{Background}
\section{System Architecture}
\section{Implementation Details}
\section{Evaluation}
\section{Related Work}
\section{Conclusion}

\bibliography{references}
\bibliographystyle{plain}

\end{document}
```

#### 2. references.bib
BibTeX formatted citations:

```bibtex
@article{gamma1994design,
  author = {Gamma, Erich and Helm, Richard and Johnson, Ralph and Vlissides, John},
  title = {Design Patterns: Elements of Reusable Object-Oriented Software},

  pages = {30--35}

  title = {Software Architecture in Practice},

```

#### 3. Makefile
```makefile
.PHONY: build clean

build:
	pdflatex manuscript.tex
	bibtex manuscript
	pdflatex manuscript.tex
	pdflatex manuscript.tex

clean:
	rm -f *.aux *.bbl *.blg *.log *.out *.toc *.lof *.lot
```

### Mathematical Formalization

Include LaTeX equations for:

**Algorithm Complexity:**
```latex
T(n) = O(n \log n) + \sum_{i=1}^{k} c_i \cdot f_i(n)
```

**Data Flow Transformation:**
```latex
\mathbf{Y} = \mathbf{W} \cdot \mathbf{X} + \mathbf{b}
```

**State Machine:**
```latex
\delta: S \times E \rightarrow S \times A
```

**System Model:**
```latex
S = (Q, \Sigma, \delta, q_0, F)
```

### Manuscript Sections

1. **Title Page** — Title, Authors, Affiliation, Date, Abstract
2. **Introduction** — Problem statement, motivation, contributions
3. **Background** — Terminology, existing approaches, technical context
4. **System Architecture** — High-level design, components, patterns
5. **Implementation Details** — Core algorithms, data structures, abstractions
6. **Workflow Analysis** — Build pipelines, execution flows, state machines
7. **Evaluation** — Capabilities, performance, scalability
8. **Related Work** — Comparison with similar systems
9. **Conclusion** — Summary, future work, limitations
10. **References** — BibTeX formatted

## Configuration

### Options
- `--depth` — Analysis level (shallow, medium, deep)
- `--format` — Output format (tex, pdf, html)
- `--citations` — Include academic citations (default: true)
- `--equations` — Include mathematical formalization (default: true)
- `--cross-ref` — Cross-reference with wiki (default: true if exists)

## Quality Standards

- LaTeX must compile without errors
- All equations syntactically correct
- Citations properly formatted in BibTeX
- Cross-references accurate
- Academic writing style (formal, precise)
- Abstract summarizes key contributions
